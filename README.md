# PlaneAlerter
A program that sends email alerts for Virtual Radar Server

This is a fork of [Dom2364/PlaneAlerter](https://github.com/Dom2364/PlaneAlerter), branched from upstream 2.6.2. There are no releases here — build from source, or get upstream's binaries from **[Download Latest Version](https://github.com/Dom2364/PlaneAlerter/releases/latest)**.

[Trello Board](https://trello.com/b/LT6Z8tPy/planealerter) (upstream)

This program uses the AircraftList.json file generated by Virtual Radar Server to retrieve current aircraft information from the radar, and compares each aircraft's data with specified conditions. If a condition matches the aircraft data, an email with the aircraft's data and a map with the track of the aircraft is sent. A log is also kept of every alert in alerts.log, containing all aircraft data in json format and the time sent.

## Changes in this fork

Everything below is a change against upstream 2.6.2.

### Email is the only alert channel

Twitter support has been removed. Upstream's Twitter integration relied on the v1.1 API that the free tier lost in 2023, so the feature could no longer work. The Twitter service and Tweetinvi package, the PIN dialog, the Twitter tab in the condition editor, the Twitter menu, the per-condition tweet settings and the "Twitter Optimised" email mode are all gone.

**Config compatibility:** `settings.json`, `conditions.json` and `emailconfig.json` from upstream still load. Twitter-related keys are ignored and dropped the next time the file is saved. One key was added: `mapboxToken` in `settings.json` (see Maps below). Files saved by this fork load in upstream too, since upstream treats the Twitter keys as optional.

### Alert emails

- **Multiple tracking links.** The single "Goto Radar" link is replaced with a `Track live on:` row linking the aircraft's ICAO to your local VRS (opened with `movingMap=1`), [airplanes.live](https://globe.airplanes.live/), [ADS-B Exchange](https://globe.adsbexchange.com/) and [OpenSky](https://map.opensky-network.org/). The OpenSky link points at the current map URL — upstream's `opensky-network.org/aircraft-profile` endpoint was retired and now returns *"This resource has been moved."* for every ICAO. The ICAO is lowercased for OpenSky only; airplanes.live and ADS-B Exchange were verified to accept the uppercase hex that VRS supplies.
- **Full flight path on the map.** Upstream drew the trail newest-first and stopped at 1000 points, so a long flight was mapped only near its end. The trail is now built oldest-to-newest and the whole path is included; points are trimmed from the *oldest* end, 10% at a time, only when the generated Mapbox static-map URL would exceed its length limit (capped at 8100 bytes). Short flights are unaffected; long ones keep their most recent track and lose the beginning instead of the end.
- **Card layout.** The email is a 600px card in the same navy / sky / amber palette as the desktop UI: a header band with registration, type and callsign, a grid of key facts (registration, callsign, type, model, operator, altitude, speed, squawk, route), the tracking links as buttons, then the map, photos and a details table with alternating rows. Images are capped at the card width so nothing overflows on a phone. A plain-text alternative view is included for notification previews and text-only clients, and all values from VRS are HTML-encoded.
- **Essentials by default.** New installs list the essential properties rather than all ~40; the *Email Content* dialog still offers All or Hidden.
- **Maps.** The Mapbox access token is configurable under *Settings > Maps*. If left blank the token hard-coded upstream is still used, with a one-time warning in the console, since that token can be revoked at any time.
- Small fixes: the garbled DOCTYPE, the "Airlines.Live" link label (now airplanes.live) and the `google.com.au` Google Maps link.

### Main window

Rebuilt. The upstream TreeView (conditions, a read-only copy of settings, and three stats) is replaced with:

- A **conditions grid**: name, alert type, trigger summary, recipient count and alerts sent this session. Double-click opens that condition in the editor. With no conditions, an empty-state panel with an *Add a condition* button replaces upstream's blocking "No Conditions!" message box.
- An **active alerts grid** with ICAO, registration, type, callsign, matched conditions, the time matched and a status column ("Tracking" or "Signal lost 45s ago"). Refreshes keep the selected row and scroll position; double-click opens the aircraft on your VRS map.
- A **toolbar** with Start/Stop, Restart, Edit Conditions and Settings, and a conventional File / Tools / View / Help menu. Donate moved under Help.
- A **status bar** showing the checker state, countdown to the next check, aircraft currently on the radar, alerts sent and uptime.
- A **console** with a filter (all messages / alert activity / warnings and errors), Copy and Clear buttons, an auto-scroll toggle, dark background with coloured text per message type, and a 4000-line cap.
- A **tray icon menu** (Show, Start/Stop, Exit) and an optional *hide to the notification area when minimised* setting.
- Window size, maximised state and splitter positions persist in `windowlayout.json`.
- A consistent colour theme (`Theme.cs`) applied to every form: navy menu, status and grid headers, sky-blue hover and selection, amber accent, flat buttons with a filled primary action.
- UI updates from the checker thread are marshalled with `BeginInvoke` instead of `CheckForIllegalCrossThreadCalls = false`.

### Settings window

Reorganised into four tabs: **Radar**, **Email**, **Alerts** and **Maps**.

- **Test connection** (Radar tab) fetches AircraftList.json with the details as typed and reports the aircraft and receiver counts, a 401 for bad credentials, or the error.
- **Use VRS location** reads the initial map position from the server's `ServerConfig.json` into the latitude/longitude fields.
- **Send test email** (Email tab) sends a short message using the SMTP settings as they are on the form, saved or not, and reports the SMTP error text if it fails.
- **Cancel button** and Esc to close. Validation runs when you click Save rather than on every close, and closing with unsaved changes asks before discarding. The main window only restarts the checker if you actually saved.
- The Gmail help link points at Google's **App Passwords** page instead of the retired "less secure apps" setting.
- Maps tab holds the Mapbox access token (with a link to get one) and the "Centre maps on" choice. Alerts tab holds the check interval, removal timeout, start-on-open, minimise-to-tray and the sound / notification / flash toggles.
- The sender email address, the AircraftList.json URL and the Mapbox token format are **validated** with a "Save anyway?" prompt. Blank fields are still allowed.

### Condition editor

Upstream's two modal windows (a list, then an editor per condition) are replaced with one window: the condition list on the left, the selected condition on the right. The controls are drawn in code to match the app theme.

- **Condition list** shows each condition's on/off state, its name and a one-line summary of its rules ("Military is yes · Altitude is below 5000 ft"). A filter box narrows the list. **+ New**, and a right-click / **⋯** menu with Duplicate, Move up, Move down and Delete. Drag to reorder, with an insertion line; order matters because of "stop checking later conditions". Deleting shows an **Undo** link instead of a confirmation box. Shortcuts: Ctrl+N, Ctrl+D, Del, Alt+Up/Down, Ctrl+F, Ctrl+S.
- **Rules read as a sentence**: "Match aircraft where *all / any* of these rules are true", then one row per rule: property, comparison, value, remove.
  - The **property picker** is a searchable popup grouped by category (Identity, Aircraft, Flight, Position and movement, Reception, Your database), with friendly names ("Type code", "Wake category", "Military") and each property's kind or unit. Typing on a closed picker starts a search.
  - **Plain-language comparisons**: is, is not, is above, is below, starts with, ends with, contains. They're stored as upstream's `Equals`, `Lower Than` and so on.
  - The **value editor fits the property**: a Yes/No switch for flags (stored as `Equals True` / `Not Equals True`), a dropdown of named values for list properties (species, wake category, engine type, ...), and a text box with the unit shown (ft, kts, ft/min, km, °) for everything else.
  - The property's description is shown under each rule, so the separate Property Reference window is rarely needed (it's still linked at the bottom).
- **Live matches**: under the name, "2 of 143 aircraft on the radar match right now", using the aircraft from the checker's last update. It recalculates as you edit and refreshes every few seconds, and hovering lists the matching aircraft.
- **Enabled switch** separate from the alert timing (First contact / Last contact / Both), so turning a condition off and on keeps its timing for the session. Only the subject fields the chosen timing uses are shown.
- **Recipients as chips**: Enter, comma, semicolon or space adds an address, pasted lists are split, invalid addresses show red, and Backspace or double-click edits one. New conditions start with the current condition's recipients.
- **Subjects**: type `[` (or use **Insert field ▾**) to pick a placeholder from a searchable list, with a live preview for a sample aircraft underneath.
- **Validation doesn't block you.** You can move between conditions freely. A condition you've left that has problems gets a warning in the list, and its problems appear next to the fields they belong to. Saving checks everything, jumps to the first problem, and only writes `conditions.json` when it's all valid. Closing with unsaved changes asks Save / Discard / Cancel.
- "Stop checking later conditions on a match" is under **More options**, with an explanation.

`conditions.json` is unchanged; a file opened and saved without edits comes back identical. The trigger-matching logic is shared between the checker and the live preview (`ConditionMatcher`).

### Other UI

- Email content config: the confirm button reads **Save** rather than "Ok", and saving writes `emailconfig.json` immediately.
- Tooltips throughout explain what each setting does.

### Repo tooling

- `Archive Project.bat` — packs the project folder to `../<folder name>.7z` with 7-Zip at maximum compression, excluding `build` and `dist`. Looks for `7z.exe` on `PATH`, then the standard Program Files locations.

## Building

Unchanged from upstream: open `PlaneAlerter.sln` in Visual Studio and build, or `dotnet build`. The project targets `net7.0-windows`; newer SDKs build it with an end-of-support warning.
