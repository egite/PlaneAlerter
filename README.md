# PlaneAlerter
A program that sends email alerts for Virtual Radar Server

This is a fork of [Dom2364/PlaneAlerter](https://github.com/Dom2364/PlaneAlerter), branched from upstream 2.6.2. There are no releases here — build from source, or get upstream's binaries from **[Download Latest Version](https://github.com/Dom2364/PlaneAlerter/releases/latest)**.

[Trello Board](https://trello.com/b/LT6Z8tPy/planealerter) (upstream)

This program uses the AircraftList.json file generated by Virtual Radar Server to retrieve current aircraft information from the radar, and compares each aircraft's data with specified conditions. If a condition matches the aircraft data, an email and/or tweet with the aircraft's data and a map with the track of the aircraft will be created. A log is also kept of every alert in alerts.log, containing all aircraft data in json format and the time sent.

## Changes in this fork

Everything below is a change against upstream 2.6.2. No settings or condition file formats changed, so configs are interchangeable with upstream.

### Alert emails

- **Multiple tracking links.** The single "Goto Radar" link is replaced with a `Track live on:` row linking the aircraft's ICAO to your local VRS (opened with `movingMap=1`), [airplanes.live](https://globe.airplanes.live/), [ADS-B Exchange](https://globe.adsbexchange.com/) and [OpenSky](https://map.opensky-network.org/). The OpenSky link points at the current map URL — upstream's `opensky-network.org/aircraft-profile` endpoint was retired and now returns *"This resource has been moved."* for every ICAO. The ICAO is lowercased for OpenSky only; airplanes.live and ADS-B Exchange were verified to accept the uppercase hex that VRS supplies.
- **Full flight path on the map.** Upstream drew the trail newest-first and stopped at 1000 points, so a long flight was mapped only near its end. The trail is now built oldest-to-newest and the whole path is included; points are trimmed from the *oldest* end, 10% at a time, only when the generated Mapbox static-map URL would exceed its length limit (capped at 8100 bytes). Short flights are unaffected; long ones keep their most recent track and lose the beginning instead of the end.

### Main window

- Default width widened from 784 to 934 px, with the condition tree, split panes and active-matches grid sized to match, so condition names and the console are both readable without resizing on every launch.
- The Statistics tree nodes ship with real names and labels (`Total Emails Sent: 0`, `Total Conditions: 0`, `Time Started: N/A`) instead of the `Node0` / `Node1` / `Node2` designer placeholders that showed until the first stats refresh.
- Active-matches grid columns now fill the available width by weight (ICAO, Reg, Type 15% each; Callsign 20%; Condition 35%) instead of sizing to content from a 5 px base.

### Settings window

- The window is **resizable** (minimum 819 × 480) instead of a fixed dialog, and the radar group box anchors to the right edge so it follows the resize.
- The sender email address and the AircraftList.json URL are **validated on close**. An address that `MailAddress` rejects, or a URL that isn't an absolute URI, raises a "Save anyway?" prompt — answering No keeps the window open instead of silently storing a value that fails at runtime. Blank fields are still allowed.
- **Refresh receivers** shows a wait cursor and disables the button while the request is in flight, so a slow or unreachable VRS no longer looks like a dead button.

### Condition editor

- Validation failures are **collected and shown once**, in a single summary dialog listing every problem ("Condition name is required", "At least one trigger is required", …). Upstream marked offending labels red with no explanation, and fired a separate message box per Twitter-mention violation.
- Required fields that fail validation also get a `*` appended to their label, which is removed once the field is valid.
- The trigger grid anchors to the right edge so it grows with the form.

### Other UI

- Condition list: Move Up / Move Down nudged right for even spacing against the Edit button.
- Email content config: the confirm button reads **Save** rather than "Ok".

### Repo tooling

- `Archive Project.bat` — packs the project folder to `../<folder name>.7z` with 7-Zip at maximum compression, excluding `build` and `dist`. Looks for `7z.exe` on `PATH`, then the standard Program Files locations.

## Building

Unchanged from upstream: open `PlaneAlerter.sln` in Visual Studio and build, or `dotnet build`. Map images still use the Mapbox access token hard-coded in `UrlBuilderService` upstream, so a heavily used instance may want to swap in its own.
